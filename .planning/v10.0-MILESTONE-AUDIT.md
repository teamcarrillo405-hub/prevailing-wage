## Unsatisfied Requirements

### MUN-02: resolveCountyRate() city-priority lookup
**Phase:** 147-municipal-local
**Claimed:** SUMMARY states "resolveCountyRate() checks city-specific rows before county-level rows"
**Reality:** Function signature is `resolveCountyRate(state, county, tradeCode)` — no city parameter. No Tier 0 city-first query. City column in county_wage_determinations is never read by the cascade.
**Impact:** NYC DDC, Chicago DOT, Seattle/King County rates can be stored in the DB but will silently fall through to county-level rates even when city rows are seeded.
**Fix required:** Add optional `city?: string` parameter + Tier 0 query `WHERE state=? AND county=? AND city=? AND trade_code=?`

## Cross-Phase Integration Issues

### Issue 1: resolveCountyRate() orphaned
`resolveCountyRate` is exported from `src/server/services/wdolSync.ts` but has **zero callers** across the entire codebase. No HTTP route, no service call, no controller references it.

**Affected flow:** Project with county → county datalist → county rate resolution (Step 4 BROKEN)
- ✅ Step 1: User selects state → datalist renders
- ✅ Step 2: User selects county → field populates
- ✅ Step 3: Project saved with county
- ❌ Step 4: resolveCountyRate() never fires — no route consumer
- ✅ Step 5: State form available in STATE_FORMS

**Fix required:** Add `GET /api/projects/:id/county-rate?trade=:tradeCode` route or wire into worker classification save flow.

### Issue 2: MUN-02 city parameter missing
See above under Unsatisfied Requirements.

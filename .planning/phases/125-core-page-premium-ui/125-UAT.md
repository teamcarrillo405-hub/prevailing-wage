## Tests

### 1. ProjectDetailPage Premium Cards
expected: Open a project's detail page. The page should show elevated card sections for Subcontractors, Wage Determinations, and Apprenticeship — each in a card with a drop shadow. Section headings use the bold Oswald headline font. Project Status shows a color Badge (green=active, gray=archived) not plain text.
result: pass

### 2. PayrollListPage Premium Cards + Week Badges
expected: Open a project's Payroll Weeks list. The list should be wrapped in a single elevated card with a "Payroll Weeks" heading and the New Week button colocated in that card header (not the page header). Each week row should be its own raised card with a status badge: "Submitted" (gray), "Final" (green), "In Progress" (yellow), or "Draft" (gray).
result: pass

### 3. PayrollWeekDetailPage Row Tints + Violation Callouts
expected: Open a payroll week with some entries. Table rows should alternate between white and a light gray tint. If any worker has a CWHSSA OT violation, an amber callout row should appear below that worker's row. If any worker is under the prevailing wage, a red callout row should appear.
result: pass

### 4. WorkersPage Elevated Cards + Filter Chips
expected: Open the Workers page of a project. Each worker should appear as an elevated card with a drop shadow and a subtle hover shadow effect. The classification/status filter chips should be pill-shaped (rounded-full) with a dark navy background when active. If no workers exist, an empty state illustration with "No workers on this project yet" and an "Add Your First Worker" button should appear.
result: pass

### 5. ReportsPage Design-Token Report Cards
expected: Open the Reports page. The report selector cards (Fringe Benefit Summary, Worker Pay History, etc.) should show elevated styling. The active/selected card should have a gold border and a faint gold background tint. Inactive cards should have a subtle hover effect (lift on hover).
result: pass

### 6. Route Transitions
expected: Navigate between any two pages (e.g., Dashboard → Project Detail → Workers). There should be a smooth 100ms fade-slide transition — the new page fades in and slides up slightly from below, rather than snapping instantly into place.
result: pass

### 7. Mobile Layout at 375px
expected: On a mobile-width screen (or with browser devtools set to 375px): The DBE stats grid and civil penalty grid on ProjectDetailPage should stack vertically. Payroll week rows should have enough height to tap comfortably (44px+). Form inputs (modals, search) should not trigger iOS auto-zoom (font size appears consistent, doesn't enlarge on focus).
result: pass

### 8. Skeleton Loading States
expected: On a slow connection (or with network throttling), navigating to a page should show a skeleton placeholder that matches the page layout — elevated card outlines with pulsing gray blocks — rather than a blank white page. PayrollWeekDetailPage specifically should show a skeleton (not a spinner) while loading.
result: pass

### 9. Empty States on List Pages
expected: On a brand-new project with no data: PayrollListPage shows an illustration with "No payroll weeks yet" and a CTA button. WorkersPage shows an illustration with "No workers on this project yet" and an "Add Your First Worker" button. ReportsPage shows "No payroll data yet" when there are no fringe entries.
result: pass

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline spacing |
| sm | 8px | Gap between stacked form fields, button group gap |
| md | 16px | Default element padding, card inner section gap |
| lg | 24px | Card default padding (`p-6`), section vertical rhythm |
| xl | 32px | Gap between Members and Invite sections on TeamPage |
| 2xl | 48px | Empty state vertical padding (`py-16` = 64px — see exception) |
| 3xl | 64px | Page-level top padding (`py-8` = 32px outer; not used for content) |

Exceptions:
- EmptyState uses `py-16` (64px) for vertical centering — established component pattern, do not override.
- Inline confirm rows use `gap-2` (8px) between action buttons — matches existing WorkersPage pattern.
- Touch targets for Remove / Revoke buttons: minimum 32px height via `py-2` (8px × 2) + content — adequate for desktop-only app.

## Typography

| Role | Size | Weight | Line Height | Font Family | Usage |
|------|------|--------|-------------|-------------|-------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 (`leading-relaxed`) | Inter | Form labels, member email, status text, help text, badge text, button-sm, inline field errors |
| Heading | 24px (`text-2xl`) | 400 (Oswald renders bold by face) | 1.2 | Oswald (`font-headline`) | PageHeader `<h1>` — "Team" page title |
| Section heading | 18px (`text-lg`) | 400 (Oswald) | 1.2 | Oswald (`font-headline`) | Card section titles: "Members", "Invite a Team Member" |

Source: existing `PageHeader`, `EmptyState`, `Button`, `Badge`, `HelpCallout` components.

Note: Only 2 effective weights used — regular (400) for body, label, and display roles; semibold (600) for buttons and emphasis elements (e.g. primary Button, bold inline text). Oswald face is inherently heavier but its weight is set by the font itself and does not constitute a declared weight variant.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f8f8f8` (`--color-surface-page`) | Page background |
| Secondary (30%) | `#ffffff` (`--color-surface-card`) | Card backgrounds (Members card, Invite card) |
| Accent (10%) | `#F5C518` (`--color-brand-gold`) | Primary CTA button fill, nav border, focus rings, "Send Invite" button |
| Destructive | `#dc2626` (`--color-status-violation` / Tailwind `red-600`) | "Remove Member" confirm button, "Revoke" text link hover |

Accent reserved for:
1. "Send Invite" primary button fill
2. Focus ring on email input field (`focus:ring-brand-gold`)
3. Nav link hover states (inherited from Layout)
4. "Transfer Ownership" primary button fill

Accent is NOT used for: badge text, member role display, section headings, or body copy.

Destructive color usage:
- "Remove Member" inline confirm button: `bg-red-600 text-white hover:bg-red-700`
- "Revoke" invite link: `text-red-600 hover:text-red-800 underline` (text link, not button)
- Transfer ownership warning text inside confirmation: `text-red-600 text-sm`

Role badges:
- Owner: `Badge variant="compliant"` → green (`bg-status-compliant/10 text-status-compliant`) — established Badge component
- Member: `Badge variant="neutral"` → gray (`bg-gray-100 text-gray-600`) — established Badge component

Invite status badge:
- Pending invite present: `Badge variant="warning"` → amber (`bg-status-warning/10 text-status-warning`)

Source: `src/client/index.css` tokens, `src/client/components/ui/Badge.tsx`, `src/client/pages/WorkersPage.tsx` destructive pattern.

## Page Layouts

### TeamPage (`/team`)

Primary focal point: Members card — the invite section is secondary. The Members card appears first and occupies full width; the Invite card follows below with `mb-8` separation.

```
<Layout>
  <main max-w-7xl px-4 py-8>
    <PageHeader title="Team" subtitle="Manage team members and invitations" />

    <!-- Members Card (primary focal point) -->
    <Card padding="default" className="mb-8">
      <h2 font-headline text-lg mb-4>Members</h2>
      <!-- For each member row: -->
      <div flex items-center justify-between py-3 border-b border-border-default>
        <div>
          <p text-sm font-medium text-text-primary>{email}</p>
          <p text-xs text-text-secondary>Joined {date}</p>
        </div>
        <div flex items-center gap-3>
          <Badge variant="compliant|neutral">{Owner|Member}</Badge>
          <!-- Owner-only controls (not shown on own row): -->
          <Button variant="ghost" size="sm">Transfer Ownership</Button>
          <Button variant="ghost" size="sm" className="text-red-600">Remove</Button>
        </div>
      </div>
      <!-- Inline confirm replaces row when Remove clicked: -->
      <!-- "Remove {email} from the team?" [Yes, Remove] [Keep Member] -->
      <!-- Inline confirm replaces row when Transfer clicked: -->
      <!-- "Transfer ownership to {email}? You will become a Member." [Yes, Transfer] [Keep Ownership] -->
    </Card>

    <!-- Invite Card (secondary) -->
    <Card padding="default">
      <h2 font-headline text-lg mb-4>Invite a Team Member</h2>
      <!-- If pending invite exists: -->
      <div flex items-center justify-between p-3 bg-gray-50 rounded border border-border-default mb-4>
        <div>
          <p text-sm font-medium>Invite pending</p>
          <p text-xs text-text-secondary>{email} — expires in {N} hours</p>
        </div>
        <Badge variant="warning">Pending</Badge>
        <button text-sm text-red-600 underline>Revoke</button>
      </div>
      <!-- Email input + Send button (disabled at capacity): -->
      <form space-y-3>
        <input type="email" placeholder="colleague@company.com" />
        <Button variant="primary" disabled={atCapacity || pendingExists}>
          Send Invite
        </Button>
        <!-- Disabled tooltip: "Team is at capacity" or "An invite is already pending" -->
      </form>
    </Card>
  </main>
</Layout>
```

## Interaction Patterns

### Inline Confirmation (Remove Member, Transfer Ownership)

Pattern established in `WorkersPage.tsx` — no modal. Row transitions to confirm state inline.

> **D-18 divergence note:** CONTEXT.md D-18 specifies a "confirmation modal" for Transfer Ownership. This spec uses an inline confirm row instead, consistent with the existing WorkersPage destructive-action pattern. Modal was not chosen because it would introduce a net-new component, and the inline pattern provides equivalent confirmation without additional implementation cost. This override is intentional.

- Remove Member: "Remove {email} from the team?" → `[Yes, Remove]` (red-600 fill) + `[Keep Member]` (ghost)
- Transfer Ownership: "Transfer ownership to {email}? You will become a Member." → `[Yes, Transfer]` (primary gold) + `[Keep Ownership]` (ghost)
- Loading state: button text changes to "Removing..." / "Transferring..." with `disabled` + `opacity-50`

### Revoke Invite

"Revoke" renders as a text link (`text-sm text-red-600 underline hover:text-red-800`) inside the pending invite row. No confirm step — revocation is reversible (owner can re-invite). Clicking fires mutation immediately; link shows "Revoking..." while pending.

### Send Invite Form

- Email input: full-width, matches existing input pattern (`border border-gray-300 rounded px-3 py-2 text-sm focus:ring-2 focus:ring-brand-gold`)
- Submit button: `Button variant="primary"` full width
- Disabled state (capacity or pending invite): button `disabled={true}` + helper text below explaining why (e.g., `<p text-xs text-text-secondary mt-2>Team is at capacity (2 members maximum)</p>`)
- API error: red banner matching existing pattern (`bg-red-50 border border-red-200 rounded px-3 py-2 text-sm text-red-700`)
- Success: clear form + query invalidation re-renders pending invite row immediately (no toast needed — UI state change is self-evident)

### AcceptInvitePage Token States

| HTTP Status | UI State |
|-------------|----------|
| Loading | `LoadingSpinner` centered in card |
| 200 OK | Show form with locked email |
| 404 Not Found | `EmptyState` heading="Invite Not Found" message="This link is not valid. Contact the person who invited you." |
| 410 Gone (expired/used/revoked) | `EmptyState` heading="Link Expired" message="This invite link has expired or has already been used. Ask the account owner to send a new invite." |
| Network error | Red error banner: "Could not verify invite link. Check your connection and try again." |

## Accessibility Contract

- All form inputs have associated `<label>` elements with explicit `htmlFor` — matches existing `LoginForm` and `RegisterForm` pattern.
- Disabled "Send Invite" button: include `title` attribute with reason text so keyboard/screen-reader users get context.
- Locked email input on AcceptInvitePage: `aria-readonly="true"` + visible helper text.
- Inline confirm rows: use `role="status"` or announce via focus management — when confirm row mounts, focus the first action button.
- Badge `role="status"` is implicit via existing Badge component — no change needed.
- Destructive buttons use `aria-label="Remove {name} from team"` to distinguish rows in a list.

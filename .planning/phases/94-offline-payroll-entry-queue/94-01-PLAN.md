  <behavior>
    - enqueuePayrollEntry(weekId, row, projectId): upserts by composite key (weekId+workerId+classificationId). If entry with same composite key exists, overwrites it (not duplicate). Sets status='pending', queuedAt=Date.now().
    - getPayrollQueue(weekId?): returns all entries (or entries for one weekId) sorted queuedAt asc. Status field: 'pending' | 'syncing' | 'synced-elsewhere'.
    - clearPayrollEntry(weekId, workerId, classificationId): deletes matching entry. No-op if not found.
    - markSyncedElsewhere(weekId, workerId, classificationId): sets status='synced-elsewhere' (server 409 — another device already submitted).
    - getPendingCount(): returns count of entries where status='pending'.
    - DB_NAME = 'payroll-queue', STORE_NAME = 'entries', version 1. Index on 'weekId' for filtered getPayrollQueue(weekId).
  </behavior>

Create `src/client/lib/payrollQueue.ts` using the `idb` library (already installed at ^8.0.3, pattern mirrors offlineQueue.ts).

Export the following:
- `PAYROLL_QUEUE_DB = 'payroll-queue'` (constant — used by SW in Phase 95)
- `PAYROLL_STORE = 'entries'` (constant — used by SW in Phase 95)
- `PayrollQueueEntry` interface: `{ id?: number; weekId: string; projectId: string; workerId: string; classificationId: string; payload: EntryPayload; status: 'pending' | 'syncing' | 'synced-elsewhere'; queuedAt: number; }`
- `EntryPayload` re-export (import from payrollWizard/useEntryMutation.ts, re-export for consumers)
- `enqueuePayrollEntry(weekId: string, projectId: string, payload: EntryPayload): Promise<void>` — uses a readwrite transaction; cursor-scan for existing entry with matching weekId+workerId+classificationId, then put() to upsert.
- `getPayrollQueue(weekId?: string): Promise<PayrollQueueEntry[]>` — if weekId provided, use the weekId index; otherwise getAll(). Sort by queuedAt asc before returning.
- `clearPayrollEntry(weekId: string, workerId: string, classificationId: string): Promise<void>` — scan and delete matching composite key.
- `markSyncedElsewhere(weekId: string, workerId: string, classificationId: string): Promise<void>` — scan matching composite key, set status='synced-elsewhere', put() back.
- `getPendingCount(): Promise<number>` — getAll() then filter status==='pending', return .length.

DB schema (openDB upgrade):
```typescript
db.createObjectStore('entries', { keyPath: 'id', autoIncrement: true });
store.createIndex('weekId', 'weekId', { unique: false });
store.createIndex('composite', ['weekId', 'workerId', 'classificationId'], { unique: false });
```

Note: idb ^8 uses openDB from 'idb'. Use lazy singleton pattern identical to offlineQueue.ts (module-level `let dbPromise`). Do NOT use IDBKeyRange for composite queries — use getAll() + filter in JS for clarity and correctness across Safari.

Purpose: This is the behavioral core of MOB-16/17. When a field worker enters payroll hours with no connectivity, every row save goes to IndexedDB with a "Queued for sync" status indicator. No data is lost. When back online, the existing flush path drains the queue.

This hook has the same external API as `useEntryMutation` plus one new status value:

```typescript
export type OfflineSaveStatus = 'idle' | 'pending' | 'saving' | 'queued' | 'conflict';

export function useOfflineEntryMutation(
  weekId: string | null,
  projectId: string,
  onLocked: () => void,
): {
  markDirty: (payload: EntryPayload) => void;
  flush: () => Promise<void>;
  saveStatus: OfflineSaveStatus;
}
```

Implementation:

1. Import and delegate to `useEntryMutation(weekId, onLocked)` for the online path.
2. Track `offlineStatus: 'idle' | 'queued' | 'conflict'` in local useState.
3. Listen to `window` 'online'/'offline' events via useEffect to derive `isOnline`.
4. Override `markDirty`:
   - If `isOnline`: call the inner `markDirty(payload)` (existing path — no change).
   - If `!isOnline` and `weekId`: call `enqueuePayrollEntry(weekId, projectId, payload)` (async, fire-and-forget with void), set `offlineStatus = 'queued'`.
   - If `!isOnline` and `!weekId`: log a console.warn, silently discard (week not yet created).
5. Override `saveStatus` computation:
   - If `offlineStatus === 'conflict'` → return `'conflict'`
   - If `offlineStatus === 'queued'` → return `'queued'`
   - Otherwise → return the inner `saveStatus` from `useEntryMutation`
6. Override `flush`:
   - When called while online, call inner `flush()` which drains the existing generic queue.
   - Also drain the payroll-specific queue: import `getPayrollQueue`, `clearPayrollEntry`, `markSyncedElsewhere` from payrollQueue.ts, iterate entries for this weekId, POST each to `/api/payroll/entries` using the existing `api.post` pattern. Handle 409 → `markSyncedElsewhere(...)`, set offlineStatus='conflict'. Handle 2xx → `clearPayrollEntry(...)`. Handle network error → leave in queue (retry next flush).
   - This dual-flush (generic offlineQueue + payroll-specific queue) ensures both GPS clock-ins and payroll entries are sent.

Type safety note: `EntryPayload` is imported from `../../lib/payrollQueue` (the version defined there). The `values` field uses `RowValues` — import it from `./Step2GridRow`:
```typescript
import type { RowValues } from './Step2GridRow';
```

Do NOT import from `useEntryMutation.ts` for types — import only the hook function. `EntryPayload` is the one in payrollQueue.ts.

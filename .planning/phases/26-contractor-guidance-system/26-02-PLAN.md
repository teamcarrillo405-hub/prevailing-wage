    Place TermTooltip inline per D-02 (inline with term wherever it appears). The 5 terms and their definitions from UI-SPEC.md:

    1. **Davis-Bacon**: "A federal law requiring contractors on federal or federally funded construction projects to pay workers the locally prevailing wage for their trade. Wages are set by the Department of Labor and published on SAM.gov."
    2. **WH-347**: "The Department of Labor's official certified payroll form. Contractors must submit it weekly to the contracting officer as proof that workers were paid the correct prevailing wage."
    3. **Prevailing wage** (or "prevailing wage"): "The minimum hourly pay rate for each trade and location, determined by the DOL based on what most workers in that area earn. Paying below this rate is a federal violation."
    4. **CWHSSA**: "The Contract Work Hours and Safety Standards Act. It requires overtime pay (1.5x base rate) for all hours over 40 in a week on federal contracts exceeding $100,000."
    5. **WD**: "Wage Determination — the specific DOL document that lists the prevailing wage rates for a given trade in a given county. Each project is assigned a WD number tied to its location."

    **Placement strategy:**

    Add `import { TermTooltip } from '../components/ui/TermTooltip';` to each page file.

    **Where to place TermTooltips:** Search each page file for occurrences of the 5 terms in visible text (JSX string content, HelpCallout body props, EmptyState message props, heading text, paragraph text). Replace the plain text occurrence with the TermTooltip component.

    **Rules for placement:**
    - In HelpCallout `body` prop strings: The `body` prop is a plain string, so TermTooltip cannot be placed inside it without changing HelpCallout's API. Instead, place TermTooltip only in JSX content areas (paragraphs, headings, list items) where the term appears as visible text.
    - In `<h1>` or `<h2>` heading elements: Do NOT wrap terms in headings — a `<span>` with an interactive button inside a heading is semantically unusual. Keep heading text plain. Only wrap terms in body/paragraph text.
    - On the landing page: Wrap terms in paragraph/description text within HowItWorksSection step descriptions and feature section descriptions. Do NOT wrap terms in the hero h1 headline.
    - Each term should have TermTooltip applied at MOST 1-2 times per page — the first meaningful occurrence. Do not wrap every single occurrence.

    **Per-page audit and placement:**

    Read each file and find where these terms appear in body text. Common locations per RESEARCH.md:
    - **LandingPage.tsx**: "Davis-Bacon" in HowItWorksSection step descriptions (step 2: "Federal law requires each worker on a Davis-Bacon job"), "WH-347" in step 4 description. Also check feature section descriptions for "CWHSSA", "prevailing wage".
    - **DashboardPage.tsx**: Check HelpCallout body (it's a string prop so cannot embed JSX — skip). Check if "Davis-Bacon" appears elsewhere in visible text.
    - **WorkersPage.tsx**: HelpCallout body mentions "Davis-Bacon" — it's a string prop, cannot embed. Check EmptyState message (also a string prop). If the only occurrences are in string props, TermTooltip cannot be placed on this page without refactoring those props to accept ReactNode.
    - **PayrollEntryPage.tsx**: HelpCallout body mentions "prevailing wage" and "WH-347" — string props. Check other visible text.
    - **PayrollWeekDetailPage.tsx**: HelpCallout body mentions "WH-347" — string prop. Check other visible text (violation labels, section headers).
    - **ProjectDetailPage.tsx**: HelpCallout body mentions "WH-347" — string prop. Check other visible text.
    - **PayrollListPage.tsx**: Check for "WH-347" in list item text or column headers.

    **IMPORTANT DECISION:** If after auditing all pages, the compliance terms appear primarily in HelpCallout `body` string props and EmptyState `message` string props (which cannot accept JSX), then refactor HelpCallout to accept `body: React.ReactNode` instead of `body: string`.

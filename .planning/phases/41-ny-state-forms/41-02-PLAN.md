Create `src/server/services/mpwrXmlGenerator.ts`:

1. Define `MpwrXmlInput` type matching the test fixture shape:
   ```typescript
   export interface MpwrXmlInput {
     project: {
       nyprcNumber: string;
       nysContractorRegNumber: string;
       name: string;
       contractorFein: string;
     };
     week: {
       weekEndingDate: string;
     };
     entries: Array<{
       workerId: string;
       workerName: string;
       workerSsnLast4: string | null;
       nysRegisteredApprentice: boolean | number;
       tradeDescription: string;
       laborType: string;
       workerAddress?: string;
       // Daily hours
       monSt: number; monOt: number;
       tueSt: number; tueOt: number;
       wedSt: number; wedOt: number;
       thuSt: number; thuOt: number;
       friSt: number; friOt: number;
       satSt: number; satOt: number;
       sunSt: number; sunOt: number;
       // Totals and rates
       totalStHours: number;
       totalOtHours: number;
       baseRateSnapshot: number;
       grossWages: number | null;
       deductions: number | null;
       netPay: number | null;
       // Fringe fields
       fringeHealthWelfare: number | null;
       fringePension: number | null;
       fringeVacation: number | null;
       fringeTraining: number | null;
     }>;
   }
   ```

2. Export `generateMpwrXml(data: MpwrXmlInput): string`:
   - Use `import { create } from 'xmlbuilder2'`
   - Create root: `create({ version: '1.0', encoding: 'UTF-8' }).ele('ProjectRollup')` — NO namespace
   - Add project-level elements: `<prcNumber>`, `<nysContractorRegNumber>`, `<contractorName>`, `<contractorFein>`, `<weekEndingDate>`
   - Group entries by workerId using a Map (workerMap pattern from WA CPR XML — lines 767-800 of export.ts). One worker may have multiple entries from different classifications.
   - For each worker group, create `<employeeWorkWeek>`:
     - `<employee>`: firstName (split workerName), lastName, ssnLast4 (use `'000000' + (entry.workerSsnLast4 ?? '0000')` for the SSN placeholder per research — BUT check research again: MPWR may use ssnLast4 directly without prefix. Use the `ssnLast4` field directly if research says so, or `000000+last4` if that is the confirmed pattern from the prompt constraints), `<nysRegisteredApprentice>` as 'true'/'false' string
     - For each classification entry for that worker, create `<workWeek>`:
       - `<workCategory>`: tradeDescription
       - `<stHourlyRate>`: baseRateSnapshot
       - `<otHourlyRate>`: baseRateSnapshot * 1.5
       - `<days>`: 7 `<day>` elements (Mon-Sun) each with `<day>` (date string), `<standardTimeHours>`, `<overTimeHours>`
       - `<supplementalPayments>`: one `<supplementalPayment>` per fringe type:
         - Health/Welfare: stHourlyRate = fringeHealthWelfare / totalStHours (or 0 if hours=0), otHourlyRate = fringeHealthWelfare / totalOtHours (or 0)
         - Vacation/Holiday: fringeVacation / hours
         - Apprenticeship/Training: fringeTraining / hours
         - Pension: fringePension / hours
         - Other: 0/0 (placeholder)
       - Add code comment: `// Supplement rate derivation: fringe total amount / total hours`
   - End with `root.end({ prettyPrint: true })`

3. Run tests — all must pass (GREEN).

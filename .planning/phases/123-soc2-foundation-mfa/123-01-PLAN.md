<objective>
Close the SEC-01 gaps: render a real scannable QR image during MFA enrollment (instead of a clickable otpauth:// text link), enforce TOTP on owner-only sensitive operations (ownership transfer + pending-invite revocation), nag owners who haven't enrolled MFA, prove the existing login-MFA gate blocks un-enrolled JWTs, and add Vitest coverage for the mfaService + /api/mfa routes + /api/auth/login MFA gate.

Purpose: Phases 78/79/83 already shipped most of the SOC 2 MFA infrastructure (TOTP columns on users, full /api/mfa route suite, two-step login gate). The remaining gaps prevent SEC-01 from being demonstrable to a SOC 2 auditor: enrollment is unscannable, sensitive owner operations bypass the second factor, owners can stay un-enrolled silently, the existing login MFA gate has no test proving it works, and there are zero tests overall.

Output: qrcode package installed; mfaService.generateTotpSecret returns a PNG data URL; /api/mfa/setup response includes qrDataUrl; MfaSetupPage renders the QR <img>; transfer-ownership and invite-revocation routes verify TOTP when caller has MFA enabled; DashboardPage shows an enrollment nag banner for un-enrolled owners; ProjectSettingsPage transfer modal includes TOTP input; Vitest unit + route tests for MFA paths AND a regression test for the /api/auth/login MFA gate.
</objective>

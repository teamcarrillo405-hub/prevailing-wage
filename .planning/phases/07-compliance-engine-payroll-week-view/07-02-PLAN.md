    - Returns 'cwhssa-ot' violation when Math.abs(grossWages - expectedGross) > 0.01 AND totalOt > 0
    - One entry can produce at most ONE violation (under-wage takes precedence over cwhssa-ot — see note below)
    - certProperPayment = true when violations contains no 'under-wage' items
    - certAccuratePayroll = true when violations contains no 'cwhssa-ot' items
  </behavior>
  <action>
    Create src/server/services/complianceService.ts following the varianceService.ts pattern.

    Exports: ComplianceViolation interface, ComplianceResult interface, computeCompliance function.

    Implementation steps:
    1. Import calculateCwhssaOt from ./calculations.js and getOrDefaultThreshold from ./otCalculator.js
    2. Import getPayrollWeek and getPayrollEntries from ./payrollService.js
    3. computeCompliance(db, weekId): async, accepts BetterSQLite3Database<typeof schema> and weekId string
    4. Load week via getPayrollWeek(weekId) — return null if not found
    5. Load entries via getPayrollEntries(weekId)
    6. Call getOrDefaultThreshold(week.projectId) to get threshold (not used for violation math — OT hours come from stored monOt..sunOt columns)
    7. For each entry: sum totalSt = monSt+tueSt+wedSt+thuSt+friSt+satSt+sunSt; sum totalOt = monOt+tueOt+wedOt+thuOt+friOt+satOt+sunOt
    8. Call calculateCwhssaOt({ baseRate: e.baseRateSnapshot, fringeRate: e.fringeRateSnapshot, totalHoursWorked: totalSt+totalOt, overtimeHours: totalOt })
    9. Skip entry entirely if e.grossWages == null (do NOT flag as violation)
    10. Compute delta = e.grossWages - result.totalWeeklyCost
    11. Violation type logic (emit AT MOST one violation per entry):
        - If delta < -0.01: violationType = 'under-wage' (underpayment — covers COMP-01)
        - Else if Math.abs(delta) > 0.01 && totalOt > 0: violationType = 'cwhssa-ot' (OT formula mismatch — covers COMP-02)
        - Else: no violation for this entry
    12. Build ComplianceResult: certProperPayment = !violations.some(v => v.violationType === 'under-wage'); certAccuratePayroll = !violations.some(v => v.violationType === 'cwhssa-ot')

    ANTI-PATTERNS (per research):
    - Do NOT re-derive OT from totalHours - 40. Use stored monOt..sunOt columns only.
    - Do NOT read from wageClassifications. Use baseRateSnapshot and fringeRateSnapshot from the entry.
    - Do NOT multiply fringeRate by 1.5 for OT hours — calculateCwhssaOt already handles this correctly.
    - Do NOT add a grossWages == null violation — null means gross not recorded, not $0 paid.

    Implementation:
    ```typescript
    import { Router } from 'express';
    import { eq } from 'drizzle-orm';
    import { requireAuth } from '../middleware/auth.js';
    import { getDb } from '../db/index.js';
    import * as schema from '../db/schema.js';
    import { computeCompliance } from '../services/complianceService.js';

    export const complianceRouter = Router();

    complianceRouter.get('/:weekId', requireAuth, async (req, res) => {
      const weekId = req.params.weekId as string;
      const userId = req.user!.userId;
      const db = getDb();

      const result = await computeCompliance(db, weekId);
      if (!result) {
        res.status(404).json({ error: 'Payroll week not found' });
        return;
      }

      // Ownership check: load project and verify userId matches
      const [project] = await db
        .select()
        .from(schema.projects)
        .where(eq(schema.projects.id, result.projectId))
        .limit(1);

      if (!project) {
        res.status(404).json({ error: 'Project not found' });
        return;
      }
      if (project.userId !== userId) {
        res.status(403).json({ error: 'Access denied' });
        return;
      }

      res.json(result);
    });
    ```

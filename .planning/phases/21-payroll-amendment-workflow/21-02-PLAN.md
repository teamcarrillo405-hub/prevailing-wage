    Near the existing `generatingRef` or `copyingRef` declaration, add:
    ```typescript

    ```

    Add handler function:
    ```typescript
    const handleAmendClick = async () => {
      if (amendingRef.current) return;
      amendingRef.current = true;
      try {
        const res = await fetch('/api/payroll/weeks/amend', {
          method: 'POST',
          headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${localStorage.getItem('token')}` },
          body: JSON.stringify({ originalWeekId: weekId }),
        });
        if (!res.ok) {
          const err = await res.json();
          alert(err.error || 'Failed to create amendment');
          return;
        }
        const result = await res.json();
        navigate(`/projects/${projectId}/payroll/${result.weekId}`);
      } finally {
        amendingRef.current = false;
      }
    };
    ```

    **Step 4 — Add "Amend This Week" button in Submission Status panel:**

    Find the section that renders when `week.submittedAt` is truthy (the submission status display area). Add the button inside that block, after the submitted info:
    ```tsx
    {week.submittedAt && !week.amendmentNumber && (
      <Button
        variant="secondary"
        size="sm"
        onClick={handleAmendClick}
      >
        Amend This Week
      </Button>
    )}
    ```

    Note: The button is hidden when viewing an amendment week itself (`!week.amendmentNumber`) — you amend the original, not the amendment. However, if the user is viewing an amendment of an already-submitted week and that amendment is itself submitted, the button should still appear. Simplify: show button when `week.submittedAt !== null`. The service handles root resolution.

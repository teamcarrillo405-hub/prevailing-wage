## SSN Input Field Contract

This is the primary new interaction in Phase 31. All decisions are locked in CONTEXT.md D-10 through D-13.

### Input Type

Use `type="password"` for the SSN input field. This masks the value as the user types (bullet characters) without requiring a JavaScript show/hide toggle implementation. The browser's native password field is appropriate for a sensitive 9-digit value.

Rationale: D-10 locks "no side-by-side dual fields." The CONTEXT.md discretion item for show/hide toggle is resolved here in favor of `type="password"` — it is simpler, has zero JS overhead, and is universally understood. The deferred item in CONTEXT.md ("SSN field show/hide toggle — Claude's discretion") does not block this choice.

### Input Attributes

```
type="password"
inputMode="numeric"
maxLength={9}
autoComplete="off"
placeholder="123456789"
```

- `inputMode="numeric"` opens the numeric keyboard on mobile without restricting input to numbers only (allows pasting)
- `autoComplete="off"` prevents browser/password manager from suggesting values
- `maxLength={9}` enforces the 9-digit ceiling at the DOM level (validation in Zod schema confirms)

### Label Text

- Add worker form: `"Social Security Number (optional)"`
- Edit worker form: `"Social Security Number"` with helper text below: `"Enter 9-digit SSN to update. Leave blank to keep current value."`

### Validation Error Messages

| Condition | Message |
|-----------|---------|
| Non-numeric characters entered | "SSN must contain only digits." |
| Less than 9 digits submitted | "SSN must be exactly 9 digits." |
| More than 9 digits (browser fallback) | "SSN must be exactly 9 digits." |

## SSN Display Contract (Masked View)

All UI locations that previously showed `SSN: ***-**-{ssnLast4}` continue using that pattern. No change to display format.

### "Full SSN not on file" Badge

- Component: `<Badge variant="neutral">`
- Copy: `"Full SSN not on file"`
- Placement: Worker detail/edit view only — NOT on the worker card list view
- Trigger condition: Worker has a non-null `ssnLast4` but `ssnEncrypted` decrypts to a 4-digit value (migrated partial)

Rationale: The card list is a scanning view — the badge adds noise without actionability. The detail/edit view is where the user can correct it by entering a full SSN.

Source: CONTEXT.md D-12; discretion resolved for placement = detail/edit view only.

## States and Interactions

### SSN Input — State Machine

| State | Visual |
|-------|--------|
| Empty / default | Placeholder `123456789` dimmed; field border `border-gray-200` |
| Typing (valid numerics) | Password masking active; no inline error |
| Typing (non-numeric pasted) | Error message appears below field immediately on change |
| Submitted — validation fail | Red error text `text-status-violation text-xs mt-1`; field border `border-status-violation` |
| Submitted — success | Form closes; masked `***-**-NNNN` appears in worker row |

### Worker Row — SSN Display States

| State | Display |
|-------|---------|
| Full 9-digit SSN on file | `SSN: ***-**-1234` in `text-text-secondary text-sm` |
| Partial (4-digit encrypted, migrated) | `SSN: ***-**-1234` + `<Badge variant="neutral">Full SSN not on file</Badge>` (detail view only) |
| No SSN on file (`ssnLast4` is null) | No SSN field shown (existing behavior, unchanged) |

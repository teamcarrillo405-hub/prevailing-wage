# Plan 151-02: ContactPage API + Landing Page Copy Fixes

## Objective

Fix the ContactPage broken mailto: submission and remove three categories of dev-placeholder text visible to real users: placeholder FAQ heading, "Short answers for the first demo" text, and "(Demo account)" testimonial attributions.

## Context

ContactPage.tsx currently uses `<a href="mailto:...">` or form action pointing to mailto: — this fails silently in Chrome/Windows. Needs a real API endpoint. LandingPage and TestimonialsPage have obvious dev placeholder text visible to every visitor, undermining credibility.

## Tasks

### Task 1: Build POST /api/contact endpoint

**Files to read first:** `src/server/index.ts` (to find where routes are registered), existing route files for pattern reference.

1. Create `src/server/routes/contact.ts`:
   ```typescript
   import { Router } from 'express';
   import { z } from 'zod';

   const router = Router();

   const contactSchema = z.object({
     name: z.string().min(1).max(100),
     email: z.string().email(),
     message: z.string().min(10).max(2000),
     subject: z.string().max(200).optional(),
   });

   router.post('/', async (req, res) => {
     const parsed = contactSchema.safeParse(req.body);
     if (!parsed.success) {
       return res.status(422).json({ error: 'VALIDATION_ERROR', issues: parsed.error.issues });
     }
     // Log the contact request (email delivery configured in Phase 151-03)
     console.log('[contact]', parsed.data.email, parsed.data.subject ?? '(no subject)');
     return res.json({ success: true });
   });

   export default router;
   ```
2. Register in `src/server/index.ts` (or the main router file): `app.use('/api/contact', contactRouter)`.

**Commit:** `feat(contact): add POST /api/contact endpoint with Zod validation`

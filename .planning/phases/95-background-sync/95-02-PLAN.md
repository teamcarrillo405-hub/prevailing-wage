Create `src/client/hooks/useSyncStatus.ts`.

```typescript
export type SyncState = 'idle' | 'syncing' | 'synced' | 'pending';

export interface SyncStatus {
  state: SyncState;
  pendingCount: number; // > 0 when state='pending'
}
```

Hook: `useSyncStatus(): SyncStatus`

Logic:
1. Track `isOnline` via useState initialized from `navigator.onLine`, updated by window 'online'/'offline' events.
2. Track `pendingCount` (number) — sum of `getQueueLength() + getPendingCount()`.
3. Track `syncState: 'idle' | 'syncing' | 'synced'` — transitions:
   - When `online` event fires: set syncState='syncing', run flush (call `processQueue()` from offlineQueue.ts — payroll-specific queue is handled by SW background sync or useOfflineEntryMutation), then set syncState='synced'. After 4 seconds, set syncState='idle'.
   - When `offline` event fires: set syncState='idle' (online indicator takes over).
4. Derived `state` to return:
   - If !isOnline && pendingCount > 0 → 'pending'
   - If syncState === 'syncing' → 'syncing'
   - If syncState === 'synced' → 'synced'
   - Otherwise → 'idle'
5. Poll pendingCount every 5 seconds (useEffect with setInterval). Also refresh on online/offline events.

Cleanup: clear all intervals and timers on unmount.

Import `processQueue` from `../lib/offlineQueue` for the online flush trigger.
Import `getQueueLength` from `../lib/offlineQueue`.
Import `getPendingCount` from `../lib/payrollQueue`.

Do NOT import `processQueue` for payroll queue — that queue drains via SW Background Sync and useOfflineEntryMutation (already wired in Phase 94).

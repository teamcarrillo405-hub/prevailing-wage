## E2E Flow Verification

### Flow 1: CA eCPR Full Export Path
1. Contractor enters payroll for CA project including fringe sub-fields (H&W, Pension, Vacation, Training)
2. `PayrollWeekForm.tsx` sends fringe fields to `PUT /api/payroll/entries/:weekId`
3. `upsertPayrollEntry()` writes fringe columns to `payroll_entries`
4. Contractor clicks "Download CA eCPR XML" — Step 1 modal opens
5. Step 1 collects FEIN, DIR Project ID, Awarding Agency, Contract Number
6. PATCH `/api/projects/:id` persists these fields before download
7. `GET /api/export/ecpr-xml/:weekId` called with query params
8. Handler calls `getPayrollEntriesWithWorkerDetails()` → `generateEcprXml()` → XML blob returned
9. File downloads; modal transitions to Step 2 checklist
10. Step 2 shows 6-item portal upload checklist with `publicworks@dir.ca.gov` link

**Status: COMPLETE** ✓

### Flow 2: WA CPR Export Path with Trade Code Gate
1. Contractor opens WA project payroll week
2. "Download WA CPR XML" button shown (isWA guard)
3. Click triggers `handleWaCprDownloadClick()`
4. If any workers have null `waTradeCode`: 422 returned, gate screen shown with edit links → contractor fixes trade codes
5. If all codes present: Intent ID modal opens, pre-filled from `project.pwiaIntentId`
6. Confirm triggers PATCH `/api/projects/:id` to persist intentId, then `GET /api/export/wa-cpr-xml/:weekId`
7. WA state gate + intentId validation + trade code check pass
8. `generateWaCprXml()` generates XML → blob downloaded
9. WAL-04 panel remains visible showing Intent to Pay + Affidavit data-entry guide

**Status: COMPLETE** ✓

# Requirements Archive: v2.0 — Contractor UX Overhaul + Compliance

**Archived:** 2026-03-20

## v2 Requirements (All Complete)

### WH-347 Correctness

- [x] **WH347-01**: User can download a January 2025-compliant WH-347 PDF (correct form version, correct field positions)
  - *Outcome: Implemented in Phase 6. Multi-page support via `pdfDoc.copyPages()` pattern. Statement of Compliance consolidated on form.*
- [x] **WH347-02**: Worker profile includes J/RA (journeyworker/registered apprentice) field — mandatory on 2025 WH-347 form
  - *Outcome: `programName` added to `worker_classifications` schema. WorkersPage shows programName input for apprentices.*
- [x] **WH347-03**: User can download WH-347 directly from the payroll week view with one click
  - *Outcome: `PayrollWeekDetailPage` has plain `<a href="/api/export/wh347/:weekId">` anchor — browser handles Content-Disposition.*
- [x] **WH347-04**: WH-347 generates multiple pages when a payroll week has more than 8 workers
  - *Outcome: Workers chunked into groups of 8 in `fillWh347()`. Page X of Y notation added.*

### Compliance

- [x] **COMP-01**: System flags payroll entries where the rate paid is below the current prevailing wage for that trade
  - *Outcome: `computeCompliance()` in `complianceService.ts`. Fires `under-wage` when delta < -0.01 for ST entries.*
- [x] **COMP-02**: System flags payroll weeks where gross wages don't match the CWHSSA formula (catches OT calculation errors)
  - *Outcome: `cwhssa-ot` violation when OT hours > 0 and expected ≠ actual. Fringe NOT multiplied for OT hours.*

### Reports

- [x] **RPT-01**: User can view a fringe benefit summary showing fringe credits per worker for a project
  - *Outcome: `GET /api/reports/:projectId/fringe-summary` aggregates by workerId. Uses fringeRateSnapshot only. `ReportsPage` Fringe Summary tab.*
- [x] **RPT-02**: User can view worker pay history — all payroll weeks, hours, gross wages, and deductions — for a worker on a project
  - *Outcome: `GET /api/reports/:projectId/worker/:workerId/pay-history` returns DESC date order. `ReportsPage` Pay History tab with worker selector.*

### Dashboard

- [x] **DASH-01**: Each project card shows a compliance status badge (green = clean, yellow = warnings, red = active violations)
  - *Outcome: `ProjectCard` fetches `/api/compliance/project/:projectId`, renders green "Clean" / red "Violations" / gray "No payroll" badge.*
- [x] **DASH-02**: Each project card shows total payroll weeks submitted and the last week number
  - *Outcome: Week count and last week number returned from compliance/project route, displayed on ProjectCard.*

### UX

- [x] **UX-01**: Project detail page shows clear navigation to Workers, Payroll Weeks, Reports, and Variance
  - *Outcome: `ProjectDetailPage` has explicit nav Links for all 4 sections. No dead ends.*
- [x] **UX-02**: Payroll weeks list shows all weeks with week number, status, and WH-347 download button per row
  - *Outcome: `PayrollListPage` has `<a href="/api/export/wh347/${week.id}">Download WH-347</a>` per row.*
- [x] **UX-03**: Worker cards show missing-data warnings (address, SSN) that block WH-347 submission
  - *Outcome: Amber inline badge "Missing data — WH-347 blocked" in WorkersPage when `!w.address || !w.ssnLast4`.*

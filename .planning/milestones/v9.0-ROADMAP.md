# Milestone v9.0: Construction ERP Integrations

**Status:** ✅ SHIPPED 2026-05-28
**Phases:** 126-134
**Total Plans:** 12

## Overview

Bidirectional sync with Procore, Sage 300 CRE, and Viewpoint Vista. Pulls workers and timesheets in from all three ERPs; pushes WH-347 compliance status back out. Built on a shared IErpAdapter interface and encrypted credential vault. Procore uses live OAuth2 PKCE; Sage 300 CRE and Viewpoint Vista use file-based adapters (directory exchange). Every adapter ships SSN-safe serializers and deduplicates workers by erp_external_id (never by name).

## Milestone Summary

**Key Accomplishments:**
1. IErpAdapter interface + encrypted credential vault + integration_connections/integration_sync_runs DB tables (Phase 126)
2. ProcoreAdapter: OAuth2 PKCE worker sync with idempotent upserts; rate-limit-aware timesheet pull with X-Rate-Limit-Reset backoff (Phases 127-129)
3. Sage300Adapter: file-based CSV worker import with path injection protection, flexible header detection (Phases 130-131)
4. VistaAdapter: file-based CSV worker import + vista_pending_actions table for async 202-polling harness (Phases 132-133)
5. FileErpCard UI: import/export directory config + manual sync trigger for Sage 300 and Vista on IntegrationsPage (Phase 126-04)
6. Integration Dashboard: sync history table (30s auto-refresh) + DashboardPage ERP failure alert banner for consecutiveFailureCount ≥ 2 (Phase 134)

**Key Decisions:**
- Sequential DB writes in adapters (never Promise.all) — SQLite single-writer rule
- File-based adapters for Sage 300 and Vista — no live REST API without third-party vendor accounts
- Worker dedup by erp_external_id + erp_source (partial unique index), never by name — avoids false positives on duplicate names
- vista_pending_actions table shipped in Phase 132 — async 202-polling infrastructure available before any Vista REST write is attempted
- SSN excluded from all ERP serializer payloads via explicit inclusion list

**Tech Debt Incurred:**
- pullTimesheets() on Procore, Sage 300, and Vista return scaffold (0 records synced) — full payroll_entry mapping deferred to post-v9.0
- pushComplianceStatus() on all three adapters return scaffold — Procore custom field write requires Procore developer sandbox; Sage/Vista file generation deferred

**Issues Deferred:**
- Full timesheet→payroll_entry mapping for all three adapters (production completion)
- Email notification on sync failure (DASH-04 partial — banner implemented, email deferred)
